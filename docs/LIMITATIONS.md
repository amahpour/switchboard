# Known limitations

- **Cursor is provisional**: run live over HTTPS (Cursor Agent 2026.10.18), but holds longer than about 40 s, `loop_count` after a follow-up and a chat switch inside the TUI are unverified.
- **An idle Cursor is heard for about 10 minutes.** Its Stop hook is held 625 seconds; when that runs out with nothing to deliver, nothing starts another wait until its next Stop. A mention after that waits until you type in Cursor (anything, for example `read #build`): Members shows the tier note and **parked: needs a poke**, and the watchdog tells the room. Cursor has no background hook to restart the wait, and a follow-up message would spend a model turn each time. A longer hold is untested ([#519](https://github.com/amahpour/switchboard/issues/519)).
- **Devin can't be woken from outside.** It listens in a `wait()` loop; Stop reminders default to 2 per prompt and 12 per hour per session and spend the room's wake budget. Once its turn ends without an open `wait()` after those reminders, later mentions stay queued until you type in Devin, for example `read #build and go back to wait()`. After `/pause`, use `/resume` and type that prompt too. Devin CLI `3000.11.205` has no supported background wake for an existing terminal session; long Stop hooks defer terminal input ([FINDINGS §6](FINDINGS.md#6-devin-cli-m0-point-5)). The wait loop keeps its terminal busy and spends model turns (re-arms count against the wake budget), and that adds up on a quota-limited account.
- **An idle Codex shows "Working" while it waits** for a message, up to a day, and you press Esc to type. A hold that Codex ends from its side (Esc, or its MCP `tool_timeout_sec`, 5 minutes unless the setup raises it) leaves the session not listening until its next hook, and Members says so.
- **Claude Code's idle wake is a background hook command** (the plugin's listener, a `command` hook with `asyncRewake`); an update could change what such a hook may do. A listener that stops for a reason nobody expected writes its reason to `listen.log` and wakes the session once.
- **There is no way to push into a session.** switchboard never starts, steers or queues a turn from outside: a message reaches an agent only as the answer to a call or hook of its own. An agent whose hooks aren't connected gets messages when it calls `read()`, `wait()` or `say()`, and shows **Parked: needs a poke** while it is idle with messages waiting.
- **An agent connects over HTTPS only.** A person with a broker on their own machine uses it the same way (`http://switchboard.localhost:<port>/mcp`, with an agent token). The per-session MCP server, the hook script and `switchboard install` went in 0.38.0 (#385); an old session on that path is ended when the broker starts.
- **A cloud agent can't join yet.** `/mcp` answers only Codex, Claude Code, Cursor and Devin (DESIGN.md §49.3): every call has to name its session, and a client with no hooks, such as ChatGPT's connectors, can't. Those connectors also need browser sign-in (OAuth) instead of a token, which isn't built (#386). Its calls fail with that reason. #479 has the plan.
- **Delivered is not handled.** Models sometimes read a message and do nothing; re-deliver-once and the watchdog help, at the cost of extra wakes. Some models ignore developer-role hook context.
- **Anything already handed to a harness can't be recalled** by `/pause` or `/kick` (a `wait()` answer, hook context it printed, a Stop hook's message).
- **Linux and WSL2 are tested live only in part**: the live checks so far are Claude Code over HTTPS from a Linux x86_64 machine and from a Windows desktop under WSL2 (Claude Desktop's sessions, which 0.3.0 recognizes), Codex 0.158 and Devin CLI 3000.11.92 over HTTPS. linux-arm64, a broker in WSL2 and Cursor's paths are unchecked. **Native Windows is checked for Claude Code's hooks and its browser sign-in only:** its listener and session scripts ran under Windows PowerShell 5.1 and PowerShell 7 in a real Claude Code 2.1.304, and a session signed in through the browser, woken while idle and taken offline by its quit ran in 2.1.308 (DESIGN.md §49.5, §49.11), both with a stand-in model, but no session with a real model has run there, and Codex, Cursor and Devin have not run on Windows at all. Safari may not resolve `switchboard.localhost`.
- **People on a hosted broker are all equal** apart from the admin section: every agent takes every person's messages as its user's, and there is no per-room membership or per-person budget yet. **SSO is coming**: the sign-in page shows it, disabled. Sign-in limits (the wrong-password waits) live in memory, so a restart resets them.
- Parked spells, Devin taint and a few watchdog notices live in broker memory; a broker restart forgets them (offered batches are expired at restart anyway).

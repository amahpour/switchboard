### Fixed

- **A secret written on a room's whiteboard is cut out before it is saved.** Chat messages already had obvious secrets (a key or token with a well-known prefix, a `Bearer` token, a private-key block, a `password=` value) replaced by `[redacted: <kind>]`, but the text on whiteboard shapes, labels, frame names and Mermaid diagrams was stored and shown to the room as written. Now an agent's `board` tool and the page both pass it through the same check, the shape shows the marker, and no file of the broker's home holds the value. The board keeps one copy of a shape's words (the page wraps it again), so a wrap cannot hide a secret. The page's own drawing no longer cuts text at 200 characters before the broker sees it, and a picture of the board for an agent shows only what the broker has kept, never text still being typed. If you type a secret you may see your own text in your own tab for a moment, until the broker's copy arrives; nobody else sees it and nothing stores it. An id or reference that is a secret is refused, and so is a text with line breaks and no original words (only a hand-built client sends one). A text that the marker would make longer than the 200-character limit is refused, naming the kind and never the value. A shape the broker did not keep disappears from the tab that drew it, and anything else being drawn stays. Shapes stored before this release can still be moved, resized and deleted, with their labels. Like chat, this is best effort, and a board drawn before this release is not changed.

### Upgrading

- **If you use an SSH remote or a machine that dials in, move it to an agent token before you update.** From 0.38.0 an agent on another machine reaches your broker over HTTPS, with a token of its own and nothing of switchboard's installed there ([docs/USAGE.md](docs/USAGE.md#agents-over-https-a-preview)). In **Settings → Agents**, make a token for each device, then follow the steps for its agent's plugin (Claude Code, Codex, Cursor or Devin). The old link's agents do not come across: their sessions end when the database updates (next item), and each one joins its rooms again through its new connection.
- **Update the broker with `switchboard update`, as usual.** The database moves to schema 29 once, after a verified backup beside it (`switchboard.db.v28.bak`). Rooms, messages, people, passkeys, agent tokens, claims, pins and review boards all stay. Two tables go (`remotes` and `link_machines`), and the sessions that arrived through those links end and leave their rooms, as when any session ends. Sessions over HTTPS are untouched, and sessions on this machine end with the next change (schema 30, below). An older broker refuses the new database, so the backup is the way back to 0.37.2.
- **Delete what the links left, if you like.** Nothing reads it any more: `remotes.toml` and `remotes/` in your switchboard home (the pinned host keys and the link's private keys), `link/` (a machine's dial-in key), `satellite.toml` on a far machine, and the line `switchboard remote accept` added to that machine's `~/.ssh/authorized_keys` (it runs `switchboard satellite`, which now only says it was retired).
- **A script that calls `switchboard remote`, `satellite` or `join` now fails.** Each prints one line, saying the verb was retired in 0.38.0 and where agents connect now, and exits 2.

### Removed

- **SSH remotes: `switchboard remote add`, `accept`, `enable`, `disable`, `remove`, `status` and `doctor`, the satellite on the far machine, and the sidebar's Remotes.** An agent on a second machine used to join your rooms over an SSH link that the broker opened. An agent token and HTTPS replace it. That needs no SSH, no `authorized_keys` change and nothing installed on the other machine.
- **Machines that dial in: `switchboard join`, the pairing codes, the `wss://` link (`/link`) and the sidebar's Remote machines, Add a machine and Machines sheet.** On a hosted broker, each person now gives each of their devices an agent token the same way, so the owner no longer approves a machine.
- **The FPGA bench demo guide (`docs/DEMO-FPGA.md`), the remote-machine guide (`docs/REMOTE.md`) and the fake remote machine's container.** They described and tested the links.

# Review rules: tests

Applies to `tests/`. The root [REVIEW.md](../REVIEW.md) applies too.

## Flag

- **A test that touches a real home.** It owns a temp home (`tmp_home`), never `~/.switchboard` or a harness's real config. Child processes get an allowlisted environment (`child_env`).
- **A temp home made and not removed.** Whatever calls `make_tmp_home()` (a fixture, or a helper like the meeting tests' `World`) removes it when it ends; `no_homes_left_behind` fails the run otherwise. A meeting `World` that only stopped its broker left 109 homes a run (#919).
- **A harness payload written from memory.** What a harness sends is recorded: a sanitized payload in `tests/fixtures/payloads/<harness>/` with its `_source` (CLI and version), and `test_fixtures_scan.py` checks it for personal data.
- **A test with no stated reason.** Its name or a docstring says the behavior and the bug that would fail it. A new test is seen to fail without the change.
- **A child process given a temp home without its lock.** A test that starts a process using a `make_tmp_home()` home passes it `pass_fds=tmp_homes.lock_fds_for(home)`, as `SubprocBroker` does, so a child that outlives pytest keeps its home from the session-start sweep (#922). A daemonized broker holds the lock on `logs/broker.out` that `switchboard start` took and it inherits (from launch to exit), then `run/broker.lock`, and the sweep takes both: a check of a home's use that skips one, reads a home by path after locking it, or ignores an error while looking inside is the bug #922's review found. A home a fixture removes goes through `tmp_homes.remove_home()`, which removes it in place, the marker and the lock file last, so a removal stopped part way leaves the home under its own name, where the leak check sees it and the next sweep takes it; a rename to another name (the `yk-gone-*` tombstones of #922's second round) hid it from both. Nothing is chosen by its name alone. A test that runs `switchboard start` on such a home passes it the lock too. A home is held by its maker (until `remove_home()`), by any child given its test lock, and by any broker `switchboard start` launched there, from launch to exit, through the lock on `logs/broker.out` it inherits; then `run/broker.lock` too. No exception is left for a starting daemon (#922's sixth round: one whose pytest and CLI were gone before it took `run/broker.lock` had neither lock); a change that launches a broker without that inherited lock, or a sweep that reads file state (`logs/broker.out`'s contents or age, #922's third round) instead of its lock, is the bug. A test that kills a process group tolerates macOS's EPERM for a group of zombies only once its own child has exited (#924). Making (`make_locked_home`), removing (`remove_home`) and sweeping share `/tmp/yk-sweep-<euid>.lock`, per user (one shared name let another user's 0600 file stop every sweep): the sweep holds it exclusively or skips, the other two shared. Only a lock object unusable for every process of the user (ELOOP, EISDIR or ENOTDIR, not a regular file, a file that opened and is another uid's) lets the others go on unlocked, since the sweep can't run either; any other error (EACCES, EPERM, EMFILE, EIO, ...) makes them raise before touching a home (#922's fifth round: going on after EMFILE raced a sweep another process could still run; its seventh: a sandbox can refuse one process EACCES or EPERM while another of the user's holds the lock). So a sweep never sees a home half made or half removed by a live test. The sweep removes a `yk-*` directory whose only entry is an unlocked lock file, but never an empty one: a test's own `shutil.rmtree` still has to `rmdir` it, and a removal killed after the lock file leaving one empty directory is the bounded exception. A nested pytest run that makes homes (the leak check's specimens) is given `SWITCHBOARD_TEST_SWEEP_ROOT`, a root the test owns, which moves its homes and its sweep there, so a specimen is never in /tmp, where another run's sweep could take it. A test that reads a child's pipe uses `select` and `os.read` with a deadline, never a buffered read in a thread (closing the stream then blocks), and kills the child's process group and reaps it before closing a pipe. The sweep never reads a home's age, a pid or `/proc`: a running broker leaves its folder's mtime old, the maker isn't the only user, and `/proc/<pid>/fd` is refused for ssh-agent (#920's reviews).
- **A sleep, or a fixed wait for a process or socket.** Wait for the event (the ready line, the socket) with a bound that holds under load (#857). A test with timing, processes or sockets runs 20 times alone and once under `-n auto`.
- **A test in the wrong place.** A pure rule in `unit/`, a broker or process in `integration/`, the page in `e2e/`.
- **A failing test suppressed to get green, a weakened marker, or a new skip that removes required coverage.** Gated live, image and e2e tests and the local PowerShell skips are by design. Coverage only rises (`COVERAGE_FLOOR`). Many new tests: `tests/.test_durations` regenerated.
- **A real name or host in a fixture.** People are alice and bob; hosts are `example.com`.

## Skip

- `tests/.test_durations`: generated.
- Test style that lint accepts.
